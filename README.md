# Отдел ИБ — расследование инцидента

[![CI](https://github.com/ShRekiSss/Ob/actions/workflows/ci.yml/badge.svg)](https://github.com/ShRekiSss/Ob/actions/workflows/ci.yml)

Браузерный терминал-тренажёр на Go для специальности **10.02.05 «Обеспечение
информационной безопасности автоматизированных систем»**. Ты стажёр отдела
ИБ: 13 последовательных заданий от первого `ls` до финального отчёта —
брифинг, поиск логов, права доступа, процессы, сеть, SSH, целостность
и упаковка доказательств.

Сюжет идёт непрерывно, без переключения режимов. Визуальный стиль —
тёмно-зелёная тема версии 1.4, только задания и тексты в стиле отдела ИБ.

### Бонус: бесконечная аркада

После прохождения (и в любой момент) доступна аркада с самолётом: кнопка
«Аркада: бесконечный бой» или команда `arcade` в терминале. Это отдельный
оверлей на canvas: он не меняет прогресс, очки и состояние сессии.

- `←`/`→` или `A`/`D` — движение, `Пробел` или мышь/тач — огонь, `P` — пауза,
  `Esc` — закрыть, кнопка «Заново» — новый бой.
- Враги бесконечно спавнятся волнами: обычный (`grunt`), быстрый зигзаг
  (`fast`) и бронированный на 3 попадания (`tank`). Каждые 12 сбитых —
  следующая волна: выше скорость и частота появления.
- 3 жизни, рекорд сохраняется в `localStorage` (если браузер разрешает);
  при 0 жизней — «КОНЕЦ ИГРЫ» и перезапуск.
- Аркада полностью в `index.html`, поэтому работает и из `file://`, и в exe.

Никакого настоящего Bash, Docker, WebSocket, базы данных или внешних
зависимостей здесь нет: одна страница, один Go-сервис, обмен «строка →
HTTP-ответ».

## Быстрый старт на Windows (без Go)

1. Открой [Releases](https://github.com/ShRekiSss/Ob/releases) и скачай
   `helios7.exe` (последний релиз).
2. Положи файл в любую папку и запусти двойным щелчком. Больше ничего
   рядом быть не должно: весь сайт, игра и мини-игра зашиты в exe.
3. Сервер поднимется на **http://127.0.0.1:8080**, браузер откроется
   автоматически. Пока открыто окно консоли — сервер работает; закрой
   окно, чтобы остановить.
4. Если Windows SmartScreen предупреждает о неизвестном издателе:
   «Подробнее» → «Выполнить всё равно». Бинарник собран из этого
   репозитория и не подписан сертификатом.

Go для этого варианта не нужен: `index.html` вшит в exe через
`go:embed`, рядом ничего не требуется.

### Автообновление

При каждом запуске exe за 1–2 секунды проверяет GitHub Releases. Если
вышла новая версия, он скачивает свежий `helios7.exe`, запускает
встроенный установщик, сам закрывается, а установщик меняет файл
и открывает новую версию. **Скачивать вручную больше не нужно** —
достаточно один раз запустить exe.

Проверка не мешает работе: если сети нет или GitHub недоступен, игра
просто запускается на текущей версии. Отключить проверку можно так:

```bat
set NO_UPDATE=1
helios7.exe
```

Если в логе появилось `x509: certificate signed by unknown authority`,
проверка обновлений сперва пробует обычный путь, затем **автоматически
повторяет запрос без проверки TLS** — обновление всё равно установится.
Это сделано для сетей, где прокси или антивирус подменяет сертификат.
Порядок действий:

1. Сверь дату, время и часовой пояс в Windows — часто проблема только в этом.
2. Если сеть использует свой корневой сертификат, положи его в `ca.pem`
   рядом с exe: тогда проверка останется включённой.
3. Принудительно отключить проверку можно так:

```bat
set NO_UPDATE_TLS_VERIFY=1
helios7.exe
```

Если порт 8080 занят, запусти из консоли:

```bat
set ADDR=127.0.0.1:9090
helios7.exe
```

## Запуск из исходников

Нужен Go 1.22 или новее.

```bash
git clone https://github.com/ShRekiSss/Ob.git
cd Ob
go run .
```

Если репозиторий уже склонирован, достаточно перейти в его каталог и
запустить `go run .` — все файлы проекта лежат в корне, отдельного
подкаталога `station-mission` нет.

Открой в браузере: **http://127.0.0.1:8080** (то же самое, что
`http://localhost:8080`).

Порт можно изменить:

```bash
ADDR=127.0.0.1:9090 go run .          # Linux/macOS
set ADDR=127.0.0.1:9090 && go run .   # Windows
```

Состояние игры хранится в памяти сервера и привязано к cookie браузера.
Перезапуск сервера сбрасывает все сессии.

## Открыть как файл, без localhost

Сервер для показа не обязателен: открой `index.html` двойным щелчком
или перетащи файл в окно браузера. Страница увидит протокол `file://`
и включит автономный режим — та же виртуальная ФС и те же команды
работают прямо в браузере, без HTTP, портов и сети.

Это удобно, когда нужно просто показать игру: адресной строки с
`localhost` нет, ничего не надо запускать. При перезагрузке страницы
миссия начинается заново.

## Как играть

Внизу страницы есть поле ввода. Введи команду и нажми Enter.
Стрелки ↑ и ↓ листают историю команд. Кнопка «Начать заново» сбрасывает
миссию и текущий каталог.

Цели миссии:

1. Посмотреть содержимое каталога `/station` — например, `ls /station`
   или `cd /station`, а затем `ls`.
2. Прочитать `brief.txt` командой `cat`.
3. Найти маркер `READY` в `events.log` командой `grep`.

Каждая цель снимает 1 HP только при первом выполнении. Повторное чтение
файла или повторный `ls` не отнимают HP ещё раз. HP вычисляется из трёх
флагов в состоянии сессии.

Подсказка под полем ввода показывает номер текущей цели (1/3, 2/3
или 3/3) и точную команду — с путями, которые подходят для твоего
текущего каталога. Например, из `/station` это `cat brief.txt`, а из
`/` — `cat /station/brief.txt`. Для очистки экрана без сброса миссии
служит команда `clear`; кнопка «Начать заново» очищает экран и
сбрасывает прогресс.

## Команды

| Команда | Что делает |
|---|---|
| `pwd` | Показывает текущий каталог. |
| `ls` | Показывает содержимое текущего каталога. |
| `ls ПУТЬ` | Показывает содержимое указанного каталога или имя файла. |
| `cd` | Переходит в корень `/`. |
| `cd ПУТЬ` | Переходит в каталог, если он существует. |
| `cat ФАЙЛ` | Выводит содержимое файла. |
| `grep СЛОВО ФАЙЛ` | Выводит строки файла, содержащие подстроку. |
| `gadget`, гаджеты | Выдаёт случайный гаджет (generator гаджетов). |
| `name ИМЯ` | Задаёт имя кадета; оно крупно появится в финале. |
| `clear` | Очищает экран терминала, но не сбрасывает миссию. |
| `help`, `?` | Показывает справку: что делает каждая команда и как писать пути. |

Набери `help` в любой момент — там для первого курса объяснены каталоги,
относительные и полные пути, `.` и `..`, а также даны примеры для каждой
команды.

`grep` намеренно упрощён: это поиск подстроки без флагов и регулярных
выражений. Строка `grep READY events.log` найдёт `READY`, а `grep READ`
тоже найдёт эту строку, но цель миссии засчитает только точный маркер
`READY`.

## Ограничения

- Разбор команды — `strings.Fields`: кавычки, пробелы в именах файлов,
  пайпы `|`, перенаправления `>` и флаги не поддерживаются.
- Все пути разрешаются только внутри виртуальной файловой системы.
  Команды операционной системы не запускаются.
- `..` не выводит за пределы виртуального корня `/`.
- Содержимое виртуальной ФС фиксировано в `game.go`; из игры его нельзя
  изменить.

## Тесты

```bash
gofmt -l .          # должен ничего не вывести
go vet ./...
go test ./...
go test -race ./...
node tools/playthrough.test.js   # полное прохождение 13 заданий офлайн
node tools/clickability.test.js  # кликабельность: форма, история, кнопка сброса
```

Покрыты:

- переходы `cd`, `pwd`, относительные и абсолютные пути;
- ошибки `cd missing`, `cd` в файл, `cat` каталога и неизвестная команда;
- однократное начисление награды за каждую цель;
- `grep` как поиск подстроки и отказ от флагов;
- полный HTTP-сценарий от старта до победы и сброс;
- независимость сессий двух игроков;
- замена просроченной cookie и очистка брошенных сессий;
- полное прохождение всех 13 заданий отдела ИБ с проверкой побочных эффектов
  (`chmod`, `kill`, `sed -i`, `tar`) и HTTP-сценария тренажёра;
- команда `clear`: сервер принимает её без ошибки и не меняет прогресс;
- имя кадета: обрезка по символам, кириллица и эмодзи не ломают UTF-8;
- соответствие версии, файлов, справки и гаджетов между `game.go` и `index.html`
  (`parity_test.go`) — офлайн-режим не может незаметно разъехаться с сервером;
  там же проверяются id и баланс тегов страницы (как `tools/check.js` в ob-master).

Те же проверки (`gofmt`, `go vet`, `go test -race`, `go build` и сборка под
Windows) выполняются в GitHub Actions при каждом push и pull request —
см. `.github/workflows/ci.yml`.

## Структура проекта

```text
Ob/
├── main.go        HTTP-сервер, cookie-сессии, API
├── game.go        виртуальная ФС, команды, цели и HP
├── linux_data.go  данные тренажёра Linux: ФС, процессы, 13 заданий
├── linux.go       логика тренажёра Linux, команды и очки
├── game_test.go   тесты игровой логики
├── linux_test.go  тесты прохождения всех 13 заданий Linux
├── main_test.go   тесты HTTP-сценария
├── parity_test.go проверка: index.html и Go-код не разъехались
├── index.html     страница: терминал, прогресс, подсказка, форма
├── tools/         Node-тесты: прохождение и кликабельность UI
├── .github/workflows/ci.yml  CI: vet, тесты, сборка
├── go.mod
└── README.md
```

HTTP API:

- `GET /` — страница игры;
- `GET /api/state` — текущее состояние;
- `GET /api/health` — `{"ok":true,"version":"...","uptime":"..."}`;
- `POST /api/command` — `{"command":"ls"}` → `{"output":"...","state":{...}}`;
- `POST /api/reset` — сброс и новое состояние.

API тренажёра Linux описан в разделе «Тренажёр Linux».

## Задания отдела ИБ (13 шагов)

Сюжет идёт непрерывно — от брифинга до финального отчёта:

| # | Команды | Навык 10.02.05 |
|---|---|---|
| 1 | `ls /station` | ориентация на узле |
| 2 | `cat /station/brief.txt` | чтение описания инцидента |
| 3 | `grep READY /station/events.log` | поиск маркера в журнале |
| 4 | `whoami`, `id` | учётная запись, UID/GID, группы |
| 5 | `ls -la`, `cat` | скрытые файлы, права |
| 6 | `find -name` | поиск логов |
| 7 | `grep -i` | поиск индикаторов без учёта регистра |
| 8 | `chmod 640` | исправление опасных прав |
| 9 | `ps aux`, `kill` | поиск и остановка процесса майнера |
| 10 | `ss -tulpn`, `iptables` | порт 4444 и блокировка IP |
| 11 | `cat`, `sed -i`, `systemctl` | укрепление SSH |
| 12 | `sha256sum` | контроль целостности |
| 13 | `tar -czf`, `systemctl` | доказательства и финал |

В цели сразу написаны точные команды и простыми словами, что каждая из них
делает (например, `ps aux — список процессов; kill 1337 — завершить процесс`).
Подсказка `hint` даёт дополнительные пояснения за −10 очков.
За каждый шаг — 100 очков, неизвестная команда −5. Прогресс хранится в cookie-сессии; в режиме `file://`
движок работает без сервера (копия логики в `index.html`, расхождения
ловит `parity_test.go`).

Страница использует API `/api/linux/state`, `/api/linux/command`,
`/api/linux/reset` — это и есть движок отдела ИБ. Старые `/api/state`,
`/api/command`, `/api/reset` остались для совместимости и обслуживают
прежнюю миссию «Гелиос-7».

## Секретный файл и скример

В `/station` лежит `secrets.txt`. Команда `cat /station/secrets.txt`
(или `cd /station`, затем `cat secrets.txt`) открывает встроенный
пиксельный GIF-скример — он зашит в `index.html` как data URI, поэтому
работает и в exe, и из `file://`. Окно закрывается кнопкой или само через
6 секунд. На прогресс это не влияет: задания и очки остаются
прежними, файл просто скрытая находка для первокурсников.

## Как устроен бекенд

- Один процесс на стандартной библиотеке Go: `net/http`, никаких фреймворков
  и внешних зависимостей.
- `index.html` вшивается в бинарник директивой `//go:embed`, поэтому exe
  самодостаточен. Версия продублирована в UI (под заголовком), чтобы сразу
  было видно, что открыта свежая сборка.
- Игровая логика (`game.go`) не знает про HTTP: `Session.Execute("ls")`
  возвращает текст и снимок состояния.
- Сервер лишь маршрутизирует запросы и ведёт сессии: при первом обращении
  выдаёт cookie `station_sid`, дальше ищет сессию по ней. Сессии лежат
  в `map` в памяти процесса, протухают через 24 часа и вычищаются.
- Каждая сессия защищена своим мьютексом, карта сессий — общим, поэтому
  два игрока не мешают друг другу и `go test -race` проходит.
- Никакой ФС компьютера не трогается: пути `cd`/`ls`/`cat` разрешаются
  только внутри фиксированной виртуальной карты `missionFS`.
- В консоли сервера печатается аккуратный баннер версии и лог каждого
  запроса: метод, путь, статус и время ответа. По Ctrl+C или SIGTERM
  сервер корректно закрывается, дожидаясь активные запросы (до 5 секунд).
- В автономном режиме (`file://`) HTTP нет вообще: та же логика
  продублирована на JavaScript внутри `index.html` — удобно показать игру
  без сервера. Код там отдельный, поэтому правки нужно вносить в оба места;
  `parity_test.go` проверяет совпадение версии, содержимого виртуальных
  файлов, справки, гаджетов и ограничения имени.
